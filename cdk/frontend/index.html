Network Troubleshooting Demo

This demo showcases how AWS DevOps Agent automatically investigates network incidents using CloudTrail, VPC Flow Logs, ELB Access Logs, and PCAP analysis via a custom MCP server on AgentCore Runtime.

🔧

6 Break/Fix Scenarios

Security groups, route tables, VPC endpoints, ALB backends, and TLS certificate mismatches — each triggers a real network failure.

🔍

Automated Investigation

CloudWatch alarms trigger webhooks to DevOps Agent, which automatically investigates using AWS APIs, logs, and MCP tools.

📡

PCAP Analysis via MCP

Scenario 6 captures network packets and analyzes TLS handshakes, SNI mismatches, and certificate details using a custom PCAP MCP server.

Getting Started

  1. Go to the Configuration tab to register the MCP server, configure the webhook, and review S3 bucket access
  2. Review the Scenarios Explanation tab to understand each scenario's alarm, traffic path, and investigation source
  3. Go to the Networking Scenarios tab to trigger break/fix scenarios
  4. Watch the investigation event stream as DevOps Agent diagnoses the issue

Webhook configuration

When a CloudWatch alarm fires, the webhook Lambda sends an HMAC-signed notification to DevOps Agent, which automatically starts an investigation. The diagram below shows the integration flow.

Go to the Agent Space console, navigate to Capabilities → Webhooks → Add webhook, and follow the instructions to generate a webhook URL and HMAC secret. Paste them below.

S3 bucket ARNs for investigation

DevOps Agent does not have S3 access by default. The Agent Space IAM role has been configured with explicit s3:GetObject and s3:ListBucket permissions on these buckets.

Scenarios Explanation

The health check app on EC2 monitors 5 connectivity paths. When a break is triggered, the corresponding check fails, publishes a CloudWatch metric, and the alarm fires within 1–2 minutes — triggering DevOps Agent via webhook.

Alarm Pipeline

Health Check Fails → PutMetricData (DevOpsDemo namespace)
→ CloudWatch evaluates (1 datapoint > 0 in 60s) → ALARM
→ SNS Topic → Webhook Lambda
→ Read HMAC secret from Secrets Manager
→ POST signed payload to DevOps Agent webhook
→ Investigation starts (~1–3 min from break)

All alarms use TreatMissingData=notBreaching — they auto-recover to OK after fix when metric data stops.
